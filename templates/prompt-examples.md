# プロンプト例（Q0〜Q4）

`[]` の中を自分の課題に置き換えて使います。60分では時間が限られるため、対象ファイル、目的、変更してよい範囲、期待する出力形式を最初の1回で伝えることを重視します。

## 使い方

- 対象ファイルは `#file:` または `@workspace` で明示する。
- 「まだ変更しないでください」を付け、読む段階と直す段階を分ける。
- 回答、差分、テスト結果、ドキュメントの内容は人が確認する。
- 機密情報、認証情報、個人情報はプロンプトに貼り付けない。
- 演習データの `internalMemo` は、具体値を引用・要約・出力させない。

## Q0: GitHub Copilot利用の最初の一歩

### 対象ファイルの役割を確認する

```text
#file:app.js

このファイルがSupport Ticket Dashboardで受け持つ役割を、GitHub Copilotを初めて使う開発者向けに1〜2文で説明してください。
続けて、次の3項目に分けて説明してください。

1. 画面から受け取る入力
2. 主な処理
3. 画面へ返す出力

「主な処理」では、このファイル内でfunctionとして定義されている関数を見つけ、
関数ごとに名前と役割を1〜2文で説明してください。
それぞれが何を受け取り、何を処理し、結果をどこで使うかを含めてください。
各説明には、根拠となる実際の変数名、関数名、またはDOM要素のIDを含めてください。
まだコードは変更しないでください。
```

### 回答が広すぎたときに絞り直す

```text
回答が広すぎました。
[対象ファイル] の [関数名] だけに絞り、実装から確認できる事実だけを説明してください。
推測は「推測」と明記してください。
```

## Q1: 既存コードをGitHub Copilotで理解する

### リポジトリ全体の関係を質問する

```text
@workspace Support Ticket Dashboardが表示されるまでの流れを説明してください。
index.html、data.js、app.js、docs/app-spec.mdを対象に、
「ファイル」「役割」「次に渡すデータ」の3列の表で回答してください。
internalMemoの具体値は引用・要約・出力せず、項目名と扱いだけを確認してください。
まだコードは変更せず、推測と確認できた事実を分けてください。
```

### 選択範囲を `/explain` で読む

```text
/explain この関数を、入力、検索、ステータス絞り込み、並び替え、件数更新、描画の順に説明してください。
検索では、入力値を検索用に整える処理と、検索対象にしているチケット項目を明示してください。
各説明に対応するコードを示してください。
```

### 呼び出し元と影響範囲を調べる

```text
@workspace [対象関数] はどのファイルから呼ばれていますか。
呼び出し元、渡している値、変更したときに影響しそうな箇所を表で示してください。
まだファイルは変更しないでください。
```

## Q2: 仕様を整理し、ドキュメント化する

### 仕様書と実装を比較する

```text
#file:docs/app-spec.md
#file:app.js

仕様書と実装を比較してください。
検索対象、ステータス表記、ソート、表示項目、期限切れ表示について、
「仕様書の記述（行番号付き）」「実装の根拠（ファイル名、関数名、行番号付き）」
「差分または要確認事項」の3列で整理してください。
internalMemoの具体値は引用・要約・出力せず、項目名と扱いだけを確認してください。
まだファイルは変更せず、実装から確認できないことは推測せず「要確認」としてください。
```

## Q3: 既存コードを安全にリファクタリングする

### 変更前の確認手順を作る

```text
#file:[対象ファイル]

[対象機能] を変更する前に、変更前後で結果が変わっていないことを確認する手順を作ってください。
操作、期待する結果の2列の表にし、各行は初期状態から独立して実行できるようにしてください。
まだコードは変更しないでください。
```

### 小さな変更計画を作る

```text
この関数のキーワード検索とステータス絞り込みを、純粋関数へ抽出する計画を作ってください。
並び替え、件数更新、DOM描画、calcの計算ルールは変更しません。
現在の検索対象と空文字の挙動を維持してください。
まず変更箇所、維持する挙動、確認手順だけを示し、まだ編集しないでください。
```

### 計画どおりに編集させる

```text
計画どおり、キーワード検索とステータス絞り込みだけを小さな関数へ抽出してください。
既存の命名とJavaScriptの書き方に合わせ、無関係な変更はしないでください。
```

### 差分を確認する

```text
現在の差分をレビューしてください。
外部から見える動作が変わっていないか、対象外のファイルに変更が入っていないかを確認し、
「変更内容」「理由」「確認方法」の3列の表で示してください。
確認できない点は「未確認」と書いてください。
```

### テスト失敗を直す

```text
/fix
次のテスト失敗を直してください。
原因を1文で説明し、修正は [対象ファイル] と関連テストだけに限定してください。

[エラーメッセージまたは失敗したテスト名]
```

## Q4: 振り返りと次の一歩

### 60分の作業を振り返る

```text
今日行った作業を振り返ってください。
「Copilotに任せたこと」「人が確認したこと」「次に改善したい依頼の仕方」の3項目でまとめてください。
このセッションの実際のやり取りから確認できる内容だけにしてください。
```

### 明日試すことを決める

```text
私の担当は [担当領域] です。
今日試した「対象を絞って質問する」「仕様と実装を比較する」「小さくリファクタリングする」のうち、
明日の業務ですぐ試せる作業を3つ、所要時間の目安つきで提案してください。
```
