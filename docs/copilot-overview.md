# GitHub Copilot の概要

## GitHub Copilot とは

GitHub Copilot は、開発者の指示や開いているコードなどをもとに、ソフトウェア開発を支援する AI ツールです。質問への回答、コードやテストの提案、変更内容のレビューなどに利用できます。

Copilot は、開発者の代わりにすべてを判断するものではありません。提案には誤りや、プロジェクトの要件に合わない内容が含まれることがあります。開発者が目的と前提を伝え、提案を確認して採用するか判断することが重要です。

## 利用シナリオ

### コード理解

処理の流れ、関数の役割、データの受け渡しを説明してもらえます。初めて触るコードでは、まず全体像をつかみ、次に気になる箇所を詳しく質問すると理解しやすくなります。

例:

> Support Ticket Dashboard で、チケット一覧を取得して画面に表示するまでの処理を説明してください。

### 仕様整理

曖昧な要望を、機能要件、確認事項、受け入れ条件などに整理できます。Copilot が推測した内容をそのまま仕様にせず、関係者に確認すべき点を明らかにするために使います。

例:

> Support Ticket Dashboard に「優先度で絞り込む」機能を追加したいです。要件、確認が必要な点、受け入れ条件を整理してください。

### 実装補助

決めた方針に沿ったコードの作成や、既存コードの小さな修正を依頼できます。対象ファイル、期待する動作、変更してはいけない範囲を具体的に伝えると、意図に近い提案を得やすくなります。

例:

> チケット一覧に優先度フィルターを追加してください。既存のステータスフィルターの実装パターンに合わせ、関係するファイルだけを変更してください。

### テスト補助

必要なテストケースの洗い出し、テストコードの作成、失敗したテストの原因調査に利用できます。正常系だけでなく、空のデータ、不正な値、通信失敗などの境界値や異常系も確認します。

例:

> 優先度フィルターについて必要なテストケースを、正常系、境界値、異常系に分けて挙げてください。

### レビュー補助

変更差分をもとに、不具合、要件の抜け、テスト不足、セキュリティ上の問題などの候補を指摘してもらえます。指摘が正しいとは限らないため、コードと要件を照らし合わせて人間が判断します。

例:

> Support Ticket Dashboard の優先度フィルターの変更をレビューし、要件漏れ、既存機能への影響、テスト不足を確認してください。

## Copilot を使うときの基本姿勢

### 1. 目的を明確にする

最初に「何を知りたいか」「何を変更したいか」「完了をどう判断するか」を伝えます。大きな依頼は、調査、計画、実装、確認に分けると結果を検証しやすくなります。

### 2. 対象ファイルを確認する

依頼する前に関係しそうなファイルを確認し、依頼後には実際に変更されたファイルを確認します。意図しないファイルや、設定、依存関係が変更されていないかにも注意します。

### 3. 変更後は人間がレビューする

差分を読み、要件との一致、動作、テスト結果を確認してから採用します。Copilot にレビューを頼んだ場合でも、最終的な判断と責任は人間にあります。

## Copilot に任せすぎないための注意点

- **回答を事実として扱わない:** 存在しない API や誤った仕様を提示することがあります。コード、公式資料、実行結果で確かめます。
- **機密情報を入力しない:** 認証情報、個人情報、社外秘情報などをプロンプトへ含めず、組織の利用ルールに従います。
- **生成コードをそのまま採用しない:** 可読性、保守性、セキュリティ、性能、ライセンス上の問題がないか確認します。
- **テストを省略しない:** コードが自然に見えても正しいとは限りません。既存テストと、変更内容に対応するテストを実行します。
- **変更範囲を広げすぎない:** 一度に大きな変更を任せず、小さな単位で差分と動作を確認します。
- **判断が必要なことを委ねない:** 要件の優先順位、リスクの受容、最終的な設計判断は、関係者と開発者が行います。

Copilot は、考える作業をなくす道具ではなく、調査や実装を速めるための共同作業者として使うことが大切です。
