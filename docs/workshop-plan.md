# ワークショップ全体設計

## 目的

GitHub Copilotをコードの自動生成だけに使うのではなく、既存コードの理解、仕様整理、ドキュメント化、安全なリファクタリングを支援する共同作業者として使う最初の実践を提供します。

受講者はSupport Ticket Dashboardを題材に、次の流れを体験します。

1. 対象、目的、制約、出力形式を明確にしてCopilotへ依頼する
2. 回答を実ファイルと照合する
3. 仕様書と実装の差分を事実と要確認事項に分ける
4. 変更前の動作を確認してから小さく編集する
5. 差分、テスト、画面動作を人が確認する

## タイムテーブル

| Session | 時間 | テーマ | 到達点 |
| --- | ---: | --- | --- |
| Overview | 5 min | ゴール、環境、起動確認 | Dashboardの12件表示と`npm test`成功を確認する |
| S1 | 5 min | 最初の一歩 | 対象ファイルを指定して質問し、回答をコードで確認する |
| S2 | 15 min | 既存コード理解 | 主要ファイルと`filterTickets`の処理を根拠付きで説明する |
| S3 | 15 min | 仕様整理と文書化 | 仕様と実装の差分候補を事実・要確認事項に分ける |
| S4 | 15 min | 安全なリファクタリング | 変更前後のテスト、差分、画面動作を確認する |
| S5 | 5 min | 振り返り | Copilotに任せる作業と人が確認する作業を説明する |
| **合計** | **60 min** |  |  |

## 守るべき演習条件

- Dashboardの初期データは架空の12件を維持する。
- `internalMemo`の具体値をプロンプトや成果物へ出力しない。
- S3で根拠を整理する前に、仕様差分を先回りして修正しない。
- S4では`tests`、`refactor`、`diff review`、`rerun tests`の順序を守る。
- Copilotの提案をそのまま採用せず、人が根拠と結果を確認する。
- 機密情報、認証情報、個人情報、未公開の顧客情報を入力しない。

## 配布方式

教材、演習アプリ、仕様、テスト、スライドはこのリポジトリに含めます。正式公開時にはこのリポジトリ自体をTemplate repositoryとして設定する想定ですが、Public化、Template repository設定、GitHub Pages有効化、公開URL確認はGitHub側の運用作業として別途実施します。
